## Goals / Non-Goals

**Goals:**
- 隔離的 nuxt-site 子專案，產生不依賴後端的品牌網站。
- 優先使用 Nuxt 內建能力及官方維護的套件；需要非官方套件時，先說明必要性與替代方案並詢問使用者，取得明確同意後才採用。
- 內容、網址與圖片可追溯，保留部落格功能並提供免費靜態搜尋。
- 以核准的首頁截圖作為桌面版視覺與內容層次依據，並依窄螢幕調整排列；截圖中的文案、肖像、標誌、作品畫面及技能資料皆可使用，正式素材待使用者提供高解析或向量版本。
- 所有必要驗收項目通過，使用者審閱後仍需另行授權上線。

**Non-Goals:**
- 不預先加入不必要的 Vuetify 或 Pinia，也不為尚未確認的需求預裝 UI 或狀態管理套件。
- 不在未取得使用者明確同意前新增、安裝、試用或整合非 Nuxt 官方套件、模組、CLI 或開發工具；Pagefind 等先前提及的候選不視為已核准。正常間接依賴的界線依下方套件決策處理。
- 不刪除或重構 Hexo，不改寫來源、根目錄依賴或部署設定，不建立 workspace。
- 不建立發布工作流程、不變更遠端 Pages、不加入部署憑證、不執行部署。
- 不加入後端、會員、留言、寄信表單、付費服務或自動內容回寫。
- 不將低解析截圖直接當作正式素材，也不虛構未經核准的作品或內容。

## Decisions

### 獨立 Nuxt 子專案與純靜態預覽

nuxt-site 使用自己的 package.json、package-lock.json、node_modules、Nuxt 設定與 .output/public。提供 dev、typecheck、generate、preview:static；generate 在頁面產生後建立搜尋索引，preview:static 只提供靜態檔案，不啟動 Nuxt 後端或 SPA fallback。連接埠與 Hexo 分開。初始化前確認並記錄 Nuxt、Nuxt Content、Node.js 相容版本及 Windows 需求。

替代方案：覆寫根目錄或 workspace 會擴大 Hexo 影響範圍；另開儲存庫不符已確認管理方式，均不採用。

### Nuxt 官方套件優先與非官方依賴核准

優先使用 Nuxt 內建能力與 Nuxt 官方維護的套件，不預先加入不必要的 Vuetify 或 Pinia。套件出現在 Nuxt Modules 目錄，或名稱含 nuxt，不代表由 Nuxt 官方維護；選用前查核官方文件與維護歸屬。

本規則涵蓋主動選用的直接依賴、開發工具、CLI 與模組。若需要非 Nuxt 官方套件，先列出套件名稱、用途、必要原因、官方或內建替代方案及取捨，詢問使用者並取得明確同意後，才能寫入依賴清單、安裝、以臨時 CLI 執行或整合。將核准結果記錄於本設計；未同意時暫停受影響工作，不以安裝後再通知代替詢問。

Nuxt、Nuxt Content 及已選框架正常安裝所帶入的間接依賴，不視為另外主動選用套件；若將其中套件提升為直接依賴或主動整合，仍須依上述規則處理。本規則不要求修改既有 Hexo 依賴。先前指定 TypeScript 的技術方向不代表新增其他第三方型別檢查或測試工具已獲核准。

替代方案：直接採用常見社群套件可減少選型步驟，但違反使用者要求，不採用。

本機驗證後的核准紀錄（2026-11-02）：Nuxt `typecheck` 需要 `vue-tsc` 才能檢查 `.vue` 元件；Nuxt Content 3.16.2 啟動時要求本機資料庫驅動。使用者已明確核准直接依賴 `vue-tsc` 3.3.14 與 `better-sqlite3` 13.0.3。`vue-tsc` 屬 Vue Language Tools，Golar 是另一個非 Nuxt 檢查器且需額外設定；`better-sqlite3` 為本機產生選用的資料庫驅動，其他 Content 資料庫驅動亦非 Nuxt 官方套件。Nuxt 官方套件或內建能力無法替代這兩項必要功能。

### 單向內容匯入與路由基準

Hexo 保持內容權威來源直到本機驗收。nuxt-site/scripts 提供匯入與檢查工具，產生 migration-manifest.json。每筆含 sourcePath、sourceHash、kind、legacyUrls、targetUrl、assets、published、exclusionReason；kind 為 article、project、about 或 excluded，排除須有理由，公開項目須有目標。資源區分本機與外部連結。

重複匯入只更新工具擁有的內容；人工編輯衝突須回報並停止，不覆寫。來源新增、修改、刪除均須顯示差異，驗收前重新同步。`Portfolio.md` 作為作品集頁及首頁作品預覽的來源，不當作最新文章；`Resume.md` 作為 About 頁的內容來源。Nuxt 目標路由分別為 `/projects/` 與 `/about/`。`legacyUrls` 可記錄兩個來源的舊 Hexo 路徑作為遷移追溯資料，但不得據此在 Nuxt 產生舊路徑頁面或轉址；已發布文章的網址相容性另依文章規格處理。文章的日期、時區、slug 與特殊語法必須依來源及 Hexo 實際路由處理，不依檔名推測或修正未來年份；僅 Portfolio.md 與 Resume.md 的 Nuxt 版本在每次產生時，將來源日期年份替換為當年，來源檔案不變。

需要 Hexo 基準時，先檢查主題掛鉤與外掛，以明確不部署的 generate 命令及隔離輸出取得；禁止根 build、部署或外部搜尋服務寫入。保留 Hexo 可用環境。

替代方案：人工複製缺乏同步檢查，移走來源破壞 Hexo，均不採用。

### 新版品牌頁路徑與舊日期網址

**Supersedes**: add-nuxt-brand-site / 單向內容匯入與路由基準

Nuxt 將 `Portfolio.md` 內容呈現在 `/projects/`，將 `Resume.md` 內容呈現在 `/about/`。不在 Nuxt 靜態輸出中建立 `/3017/12/01/Portfolio/`、`/3017/12/03/Resume/` 頁面、別名或轉址，也不將這兩個來源路徑列為 Nuxt 的 canonical 或 sitemap 頁面。既有 Hexo 不因此修改；Nuxt 對已發布文章的舊網址相容性維持原規格。

取捨：新版採用符合導覽語意的乾淨路徑，舊站與文章網址不受影響；直接開啟兩個舊品牌頁路徑不會由 Nuxt 提供內容或轉址。

### Nuxt 品牌頁日期年份採用產生當年

**Supersedes**: add-nuxt-brand-site / 單向內容匯入與路由基準（品牌頁日期年份規則）

每次執行 Nuxt 靜態產生時，Portfolio.md 與 Resume.md 的 Nuxt 版本日期年份必須採用產生當下的日曆年份，月份與日期沿用來源日期。此轉換只套用於 Nuxt 產生結果，不寫回來源檔案，也不改變 Hexo。品牌頁 URL 固定為 `/projects/` 與 `/about/`，日期年份不構成路由；文章的未來日期與實際舊網址維持原樣。驗收時以固定系統日期的產生測試確認兩頁年份同步變更，來源檔案雜湊及 Hexo 設定保持不變。

替代方案：沿用來源年份會讓新版品牌頁帶有 3017 年；修改來源則會改變 Hexo 行為，均不採用。

### 使用者確認品牌視覺與內容

使用者核准提供的首頁截圖作為桌面版視覺基準。首頁依序呈現導覽與個人主視覺、最新文章、作品集、技能及頁尾；沿用截圖中的粉紅、薄荷綠、深藍與淡色區塊、手寫風格名稱、襯線文字、圓形肖像框及波浪分區。導覽項目、標語、肖像、文章卡片、作品畫面和技能資料均已核准使用。低解析截圖僅供版面參考，正式素材須等待使用者提供高解析或向量檔。

手機版保留相同內容層次與視覺語言，依窄螢幕調整版面及導覽，不照搬桌面排列。色彩與字型規格圖已提供色碼、字型、字重、字級、文字框尺寸與文字字距；首頁英文草寫姓名使用 Satisfy，這個字型的字重與尺寸尚未指定。區塊間距、版面尺寸及圖示套件尚未提供，待使用者提供 Figma 量測或規格後再確認，不得自行將估值當成精確值。共用導覽、頁尾、版型與樣式，不預先加入不必要的 Vuetify 或 Pinia。

替代方案：未經確認套用現成主題無法保證品牌需求，不能算完成。

### 首頁英文草寫姓名使用 Satisfy

**Supersedes**: add-nuxt-brand-site / 使用者確認品牌視覺與內容（姓名字型待補部分）

首頁主視覺中的英文名字使用 Satisfy 字型，不以其他手寫字型替代。使用者只指定字型家族；字重、字級、字型檔來源與字型尺寸尚未指定，不得自行宣稱為已核定的設計值。驗收時確認桌面與手機預覽的英文名字確實以 Satisfy 顯示；其餘文字仍依 Design Source 字型表。

替代方案：沿用未定字型或使用系統手寫字型會造成品牌主視覺不一致，不採用。

### 靜態導覽與免費搜尋

Nuxt Content 集合驗證欄位。文章列表依日期降冪，同日期依網址升冪；每頁十篇，沿用既有每頁設定值。品牌首頁不再是文章列表，新文章首頁為 /blog/；已發布文章與必要導覽入口仍有靜態相容頁，作品集與 About 內容分別使用 /projects/ 與 /about/，不為其舊日期網址產生相容頁或轉址。所有內容與頁碼路由明確納入預先產生。

搜尋先評估 Nuxt 官方內容能力能否滿足免費靜態搜尋與中文查詢。Pagefind 僅保留為未核准的非官方候選；若官方方案不足，先向使用者說明原因與 Pagefind 或其他替代方案的取捨，取得明確同意後才安裝、執行相容性試驗及整合。確認 Windows、Nuxt 輸出與中文查詢後，再於頁面產生後建立公開文章及作品正文索引，排除草稿及重複導覽。若不相容，再回報並取得替代方案確認，不切換付費服務。搜尋須處理載入、命中、無結果與索引錯誤。

保留 /atom.xml，內容與公開文章一致，使用設定的正式網址；新增 sitemap 與 canonical metadata，不列草稿或重複相容頁為 canonical。

替代方案：Algolia 增加外部服務依賴，純 SPA 不能作為深層靜態路由的替代，均不採用。

### 本機驗收與部署分離

「90%」不是測量通過率。型別、產生、內容、圖片、網址、導覽與搜尋等必要檢查全部通過；一般靜態伺服器能直接開啟及重新整理內頁，未知網址回應 404。使用者審閱桌面、手機、鍵盤操作與正式內容，僅明確接受的非阻擋視覺細節可延後。

正式切換為後續另行授權階段，必須確認 annilla／annila 拼字、目標儲存庫、Pages 來源、是否跨儲存庫發布及最小權限，保留舊站可重新部署版本與回復操作，再建立手動或有核准門檻的免費流程。本次不建立或執行這些發布步驟。

替代方案：推送自動覆蓋正式站或以本機驗收推定授權，均違反使用者界線。

## Implementation Contract

- 範圍：新增 nuxt-site；.gitignore 僅補產物忽略、README.md 僅補操作說明；Spectra 文件依任務更新。不改寫 source、themes、_config.yml、根套件、鎖定檔或遠端設定。
- 依賴：優先 Nuxt 官方套件；非官方直接依賴與工具須先詢問並取得明確核准，包含搜尋、UI、狀態管理、型別檢查與測試工具。驗收核對新增依賴的維護歸屬及核准紀錄，不得以 Nuxt Modules 上架代替官方歸屬證據。
- 指令：從 nuxt-site 執行 npm run dev、npm run typecheck、npm run generate、npm run preview:static、npm run content:import、npm run content:check。失敗輸出含具體來源或網址及原因，結束碼非零，不能用空內容冒充成功。
- 清單：公開項目有 targetUrl，排除項目有 exclusionReason；缺少本機資源、大小寫不一致、重複目標路由、非法日期、不支援語法、來源未同步或人工修改衝突均阻擋驗收。
- 內容：盤點時量測到的 83 份 Markdown 只作基準資訊，驗收以當下清單逐筆核對；保留來源內容與已發布文章的實際公開網址，文章不自動修正未來年份。`Portfolio.md` 與 `Resume.md` 在 Nuxt 分別使用 `/projects/`、`/about/`；每次產生新版時，Nuxt 版本日期年份採用當年並保留來源月份、日期。舊日期網址只作遷移追溯資料，不產生 Nuxt 頁面、別名或轉址；來源檔案與 Hexo 不變。
- 驗收：型別及靜態產生成功；無後端即可直接存取所有公開路由，核對資源、分類、標籤、彙整、分頁、RSS、sitemap 與搜尋。索引建置失敗必須讓 generate 失敗。
- 門檻：視覺、素材或分類未確認時停止相關任務；人工審閱未通過不標完成。本機通過不代表授權部署。

## Risks / Trade-offs

- [Hexo 語法與圖片無法直接搬移] → 逐類盤點轉換並檢查輸出。
- [Windows 掩蓋大小寫問題] → 精確比對檔案清單，未來上線仍驗證 Pages。
- [兩份內容分岔] → 單向匯入、來源雜湊、人工修改衝突檢查，驗收前同步。
- [遺漏深層頁面] → 逐一對照清單與輸出，以無 fallback 的伺服器直接請求。
- [Node.js／Nuxt Content 環境不相容] → 初始化前確認版本並保留 Hexo 的既有可用環境。
- [本機通過不代表線上通過] → 後續另行授權時驗證 HTTPS、大小寫與回復方式。

## Migration Plan
